# Research Paper AI — 3-Level LLM Fallback

This backend removes the Gemini dependency from the RAG answer-generation
step.

## Architecture

```text
                    User question
                          |
                          v
                Local embedding model
              all-MiniLM-L6-v2
                          |
                          v
                 Retrieve top-k chunks
                          |
                          v
                    RAG prompt
                          |
                          v
              +-----------------------+
              |   LLM FALLBACK CHAIN  |
              +-----------------------+
                    |
                    v
          1. Groq / GPT-OSS 20B
                    |
             if unavailable
                    v
          2. OpenRouter / free router
                    |
             if unavailable
                    v
          3. LM Studio / GPT-OSS 20B
                    |
                    v
                    Answer
```

## Important

The RAG system is no longer named or hard-coded for PPO.

Your embeddings JSON should eventually contain chunks from every uploaded
research paper. The RAG code supports:

- paper name
- paper ID
- page
- section
- chunk ID
- text
- embedding

Older chunk files containing only `chunk_id`, `page`, `section`, `text`, and
`embedding` also work.

## 1. Install dependencies

Activate your existing environment:

```bash
conda activate aiml
```

Then:

```bash
pip install -r requirements.txt
```

## 2. Create `.env`

Copy:

```text
.env.example
```

to:

```text
.env
```

Then put your keys into `.env`.

Do NOT commit `.env` to GitHub.

## 3. Groq

Set:

```text
GROQ_API_KEY=your_key_here
GROQ_MODEL=openai/gpt-oss-20b
```

Groq currently supports `openai/gpt-oss-20b`.

## 4. OpenRouter

Set:

```text
OPENROUTER_API_KEY=your_key_here
OPENROUTER_MODEL=openrouter/free
```

`openrouter/free` is OpenRouter's free-model router. It automatically chooses
from currently available free models.

If you later want a fixed OpenRouter model, replace the value with that model's
current model slug.

## 5. LM Studio

Open LM Studio.

Load:

```text
gpt-oss-20b
```

Start the local server from the Developer tab.

Default:

```text
http://localhost:1234
```

The backend uses:

```text
http://localhost:1234/v1
```

Check that LM Studio exposes the model as:

```text
openai/gpt-oss-20b
```

If LM Studio displays a different identifier, change:

```text
LM_STUDIO_MODEL=...
```

## 6. Run

From the project root:

```bash
python retrieval/rag.py
```

## 7. What happens during a request

If Groq works:

```text
[LLM] Using Groq → openai/gpt-oss-20b
[ANSWER GENERATED BY] Groq → openai/gpt-oss-20b
```

If Groq is unavailable:

```text
[LLM] Groq unavailable (...). Falling back to OpenRouter...
[LLM] Using OpenRouter → openrouter/free
```

If OpenRouter also fails:

```text
[LLM] OpenRouter unavailable (...). Falling back to LM Studio...
[LLM] Using LM Studio (local) → openai/gpt-oss-20b
```

The user therefore gets an answer instead of a Gemini 503/429 traceback.

## 8. Gemini

Gemini is no longer required by this backend.

You can remove the old:

```python
from google import genai
```

and the Gemini client code from the RAG system.

## 9. Current project limitation

The LLM fallback is now generic, but the ingestion/indexing side still needs to
be generalized if the current embeddings file is named `ppo_embeddings.json`
and contains only the PPO paper.

The final architecture should be:

```text
PDF upload
   |
   v
PDF text extraction
   |
   v
Chunking
   |
   v
Local embeddings
   |
   v
Research-paper vector/index store
   |
   v
Retriever
   |
   v
Groq -> OpenRouter -> LM Studio
   |
   v
Answer + paper/page sources
```

The UI can be built separately later with Lovable.
